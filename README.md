# CampusCare prototype

A responsive browser prototype for the Aditya University campus pharmacy concept. Open `index.html` in a modern browser.

## Included

- Student symptom/support request form with consent, urgent-help messaging, block and pickup selection, and attachment preview/removal.
- Separate known-medicine request flow with sample catalog search, quantity controls, estimated sample total, and pharmacist review caveat.
- Sample student request list and simulated pharmacy/EV runner workflow. The runner view shows destination and status only; the pharmacy view can review the student's note.
- Campus guide illustration, help entry point, privacy messaging, mobile navigation, and responsive styling.

## Prototype limits

This is a front-end-only demonstration. Requests, role selection, and status changes exist only in the current page session. There is no backend, persistent database, real authentication, server-side authorization, secure upload storage, real inventory, pharmacy connection, or notification service. The demo role switch is not access control. Do not enter real student health information or upload real prescriptions/photos.

Before a campus pilot, connect the interface to an approved backend with authenticated student, pharmacist, runner, and administrator roles; private medical-data storage and access auditing; secure file validation/retention; pharmacy inventory and approval operations; verified campus contacts and locations; and institution/Apollo approval. Configure actual notification and delivery-estimation services as needed.

All people, requests, stock, prices, hours, and status data shown are synthetic examples. Delivery timing is a non-guaranteed target.
